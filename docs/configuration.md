# Configuration

Every environment variable Harness AI reads, with its default and what it changes. All are read once at startup; changing any of them needs a restart.

← Back to the [README](../README.md).

---

## Environment Variables

| Variable | Required | Default | Description |
|---|---|---|---|
| `OPENROUTER_API_KEY` | Yes, unless `PROVIDERS_FILE` is set and no provider uses it | — | API key used to call the upstream LLM provider via OpenRouter. With `PROVIDERS_FILE` set, each provider names its own key variable (`key_env`), and this one is required only if a provider names it. See [Providers](features.md#providers). |
| `ADMIN_TOKEN` | Yes | — | Break-glass bearer token that always resolves to the `admin` role, independent of the `users` table. Not the primary auth mechanism — issue individual tokens with `scripts/manage_users.py` instead. **Never accepted on `/v1`**, the OpenAI-compatible endpoint (PRD-015); `BREAK_GLASS_INGRESSES` can also refuse it on `POST /query` and the chat UI. The admin console signs in with it regardless. It carries the `admin` role's usage limits. |
| `DATABASE_URL` | Yes | — | libSQL endpoint for the `audit_logs` and `users` database: `libsql://<database>-<org>.turso.io`, `https://...`, or `http://127.0.0.1:8080` for the local dev server. No default, and a `sqlite:` value is a startup error — the local-file path was removed deliberately, not deprecated. |
| `TURSO_AUTH_TOKEN` | Yes for remote | — | Bearer token for the database. Required whenever `DATABASE_URL` is `libsql://` or `https://`; unused by the local `http://` dev server, which takes no token. Never logged — configuration errors quote the URL's scheme only, never the URL itself. |
| `DB_BOOTSTRAP_ENABLED` | No | `true` | Whether startup probes the database and applies the schema. The only sanctioned `false` is the Docker builder stage, where the image must build with no database reachable. `false` in a running deployment boots an application whose schema was never created. |
| `PORT` | No | `8000` | Port the FastAPI server listens on. |
| `HOST` | No | `0.0.0.0` | Host/interface the server binds to. |
| `LOG_LEVEL` | No | `INFO` | Log verbosity (`DEBUG`, `INFO`, `WARNING`, `ERROR`). |
| `RBAC_ENABLED` | No | `true` | Deny-by-default authorization enforcement. `false` preserves exact pre-RBAC (PRD-001) behavior — a documented migration escape hatch, not a normal operating mode. |
| `RBAC_DEFAULT_ROLE` | No | `user` | Role assigned by `scripts/manage_users.py create-user` when `--role` is omitted. |
| `RBAC_ROLES_FILE` | No | — (empty) | Optional path to a JSON role→permission matrix overriding the built-in default. A malformed file or an unrecognized permission fails startup rather than silently falling back. The matrix can also grant the six `action:*` permissions (`action:sql:write`, `action:sql:ddl`, `action:shell:exec`, `action:fs:write`, `action:net:egress`, `action:secret:read`), which no built-in role holds; the file replaces the whole matrix, so restate every role. See [Action policy rules](features.md#action-policy-rules). |
| `MODEL_ALLOWLIST` | No | `gpt-4,claude-3-sonnet,openai/gpt-4o,anthropic/claude-3.5-sonnet` | Comma-separated models a `user`-role caller may request. Validated server-side; `admin` bypasses this list entirely. Ignored in file mode (`PROVIDERS_FILE` set): the registry's models and roles decide. |
| `PII_REDACTION_ENABLED` | No | `true` | Master switch for PII redaction under **every** profile, `chat` and `code` alike: prompts, history, and responses where the profile redacts them. `false` also disarms the `code` size limit, since nothing is analyzed. Set to `false` to skip all NLP work (and the model download requirement). |
| `PII_SCORE_THRESHOLD` | No | `0.35` | Under the `chat` profile: minimum Presidio confidence for an entity to be masked. Deliberately low — the project favors over-masking over missing real PII. `code` uses `PII_SCORE_THRESHOLD_CODE`. |
| `PII_ENTITIES` | No | `PERSON,EMAIL_ADDRESS,PHONE_NUMBER,CREDIT_CARD,US_SSN,IBAN_CODE,LOCATION` | Under the `chat` profile: comma-separated list of Presidio entity types to detect and mask. `code` uses `PII_ENTITIES_CODE`. |
| `PII_NLP_MODEL` | No | `en_core_web_lg` | spaCy model backing the `chat` profile's analyzer — and `code`'s only if `PII_ENTITIES_CODE` names a named-entity type. This is the only model the Dockerfile and the Quickstart install; naming a different one (e.g. `en_core_web_trf`) makes spaCy try to download it at startup, which is slow and fails outright if the name is unresolvable or the package needs a C++ toolchain to build. |
| `CHAT_HISTORY_ENABLED` | No | `true` | Master switch for chat transcript persistence. `false` writes no transcript, reads none, and renders no session rail — the chat behaves exactly as it did before this release, from the same image. A supported configuration for a deployment that must not hold prompt text at rest, not a degraded mode. It governs the transcript only: a `session_id` sent to `POST /query` is still recorded on the audit row. |
| `CHAT_SESSION_LIMIT` | No | `50` | How many chats the session rail lists per user. The rail states its window against your real total, so a capped list never reads as a complete one. A value below `1` is a **startup error**, not a clamp — an empty rail on an account that has chats is a silent lie. To turn persistence off, set `CHAT_HISTORY_ENABLED=false` instead. |
| `OPENROUTER_TIMEOUT_SECONDS` | No | `120.0` | How long to wait for the upstream model provider, in seconds. Was a hard-coded 30 s, which is too short for a long conversation. Must be greater than `0` — a non-positive value would either hang forever or fail every call instantly, so it is a **startup error**. In file mode this is only the default for a provider's `timeout_seconds`. |
| `CONTEXT_MAX_MESSAGES` | No | `100` | Most messages a conversation may carry into the pipeline, counting every user and assistant turn plus the new one. Checked before `CONTEXT_MAX_CHARACTERS`, and the only limit reported when both are broken. The chat UI trims to fit before sending; a conversation still over it is refused. Must be at least `1`. |
| `CONTEXT_MAX_CHARACTERS` | No | `200000` | Most characters a conversation may carry, summed over message contents. **Characters, not tokens** — a deliberate proxy, since counting tokens means carrying a per-model tokenizer the harness does not have. Roughly 50k tokens of English; code runs denser. Must be at least `1`. |
| `PIPELINE_MAX_WORKERS` | No | `32` | Threads in the dedicated pipeline executor. The whole pipeline runs here rather than on the server's shared pool, which is what keeps `/health` and other queries answering while long upstream calls are in flight. Sizing it below the number of concurrent sends queues them; it does not drop them. Must be at least `1`. |
| `AUDIT_BUFFER_DIR` | No | `./var/audit-buffer` | Directory of the audit journal (PRD-018): where an audit row is written when the database cannot take it. Created when the application starts, never at import; `0700` on POSIX, files `0600`, because it holds raw prompt previews. Empty while the database is reachable. The compose file overrides it to `/var/lib/harness/audit-buffer`, the `harness-audit-buffer` named volume. An empty value is a **startup error**. See [What a database outage does](deployment.md#what-a-database-outage-does). |
| `AUDIT_BUFFER_MAX_BYTES` | No | `67108864` | Capacity of the audit journal in bytes (64 MiB). An append past it fails closed (the request gets a `503`). Must be at least `PIPELINE_MAX_WORKERS` × 65536 × 2 (4 MiB at the default 32 workers), so each worker has a reserved entry plus room to spare; a smaller value is a **startup error** that names both settings. |
| `DRAIN_FILE` | No | `/tmp/harness-drain` | Path of the drain flag (PRD-019). While the file exists, `GET /ready` answers `503` with reason `draining`, so the load balancer stops routing new requests to the instance; `/health` ignores it. `scripts/rolling_restart.sh` creates it inside the container. A non-empty absolute path (POSIX or Windows) is required: anything else is a **startup error**. Nothing is created at startup. See [Multiple instances](deployment.md#multiple-instances). |
| `READY_DB_TIMEOUT_SECONDS` | No | `2.0` | Deadline in seconds of the one `SELECT 1` behind `GET /ready` (PRD-019). Must be greater than `0` and at most `10`, otherwise a **startup error**; keep it under the balancer's health timeout (3 s in `deploy/lb/Caddyfile`). |
| `LB_COOKIE_SECRET` | Only with `docker-compose.lb.yml` | — | Secret that signs the balancer's `harness_lb` affinity cookie (PRD-019). Read only by the `lb` service in `docker-compose.lb.yml`, never by the application; compose refuses to start without it. Generate one with `openssl rand -hex 32`. See [Multiple instances](deployment.md#multiple-instances). |
| `REFLEX_REDIS_URL` | No | — (leave unset) | A Reflex variable, not a harness setting (PRD-019 Section 6.2). Setting it silently switches Reflex to Redis state storage, which is untested; leave it unset, also with several instances. |
| `PATTERNS_FILE` | No | — (empty) | Path to a YAML file of pattern lists and profiles; [`examples/patterns.yaml`](../examples/patterns.yaml) is a working sample. Empty uses the built-in policy and reads no file. A file **replaces** the built-in policy wholesale — nothing is merged — and a missing, malformed or invalid file is a **startup error** naming the list and the rule that failed, never a silent fallback. See [Pattern policy](features.md#pattern-policy). A key written twice anywhere in the file stops startup, naming the key and both lines (PRD-016 D13); PyYAML used to resolve it silently to the last one. |
| `PATTERN_PROFILE_DEFAULT` | No | `chat` | The profile `POST /query` and the chat UI run. Must name a profile the loaded policy defines — checked when the policy loads at startup, so a typo is a **startup error**, not a failure on the first request. A request cannot choose a profile. |
| `PATTERNS_ALLOW_REGEX` | No | `false` | Whether `match: regex` lists are permitted at all. Off, a file containing one fails startup; on, each regex must still compile and pass the nested-quantifier check. Turning it on is the deliberate act that stands between a badly written pattern and a hung worker. |
| `PATTERN_MAX_SCAN_CHARACTERS` | No | `1000000` | Most characters of any one message a pattern scan runs over. A longer message is matched on its first part only and a `WARNING` is logged; what is sent upstream is never truncated. A backstop far above anything `CONTEXT_MAX_CHARACTERS` admits by default. Must be at least `1`. |
| `PII_ENTITIES_CODE` | No | `EMAIL_ADDRESS,PHONE_NUMBER,CREDIT_CARD,US_SSN,IBAN_CODE` | Presidio entity types detected under the `code` profile. With no named-entity type (`PERSON`, `LOCATION`, `ORGANIZATION`, `NRP`, `DATE_TIME`) in the list, a tokenizer-only analyzer runs and `en_core_web_lg` is never loaded for `code`; adding one masks names or places at `chat`'s cost. An empty list or an unknown name is a **startup error** — to turn redaction off, use `PII_REDACTION_ENABLED`. See [PII redaction](features.md#pii-redaction). |
| `PII_SCORE_THRESHOLD_CODE` | No | `0.40` | Minimum Presidio confidence to mask an entity under `code`. Set from the benchmark: the highest value at which every PII sample in the prose corpus is still found. Outside `0`–`1` is a **startup error**. |
| `PII_MAX_CHARACTERS_CODE` | No | `200000` | Most characters `code` will analyze in one request, counted over the roles it redacts with fenced content and line breaks left out. Over it the request is **refused** with `limit: "redaction_characters"` and audited — never forwarded unmasked. Must be at least `1`. |
| `PII_CODE_REDACT_OUTPUT` | No | `false` | Redact the model's response under `code`. Off because a coding agent writes its response into files, where a placeholder corrupts them; on, if any unmasked output is worse than that. |
| `PII_CODE_REDACT_SYSTEM` | No | `false` | Redact `system` turns under `code`. Off because it is the client's own prompt and the largest fixed cost per request; on for a deployment that distrusts its clients' prompts. |
| `PII_CODE_SKIP_CODE_BLOCKS` | No | `true` | Skip fenced code blocks under `code`. On, PII inside a fence reaches the provider unmasked while prose and inline backtick spans are still masked; off, fenced code is analyzed too, at the risk of placeholders in code. |
| `USAGE_LIMITS_ENABLED` | No | `true` | Master switch for the usage gate and the token charge. On by default, so an upgraded deployment is limited from its first boot. `false` writes and reads no counter, and each request makes the three round trips it made before. Independent of `RBAC_ENABLED`, which does not turn limits off. See [Usage limits](features.md#usage-limits). |
| `USAGE_DAILY_TOKEN_BUDGET` | No | `*=1000000` | Tokens per user per UTC day, by role: `role=value` pairs with a required `*` entry, each value a whole number of at least `1` or `unlimited` — e.g. `*=1000000,admin=unlimited`. A missing `*`, a role named twice, `0` or any other value is a **startup error** naming the setting. A starting point, not a recommendation; per-user overrides are set with `scripts/manage_users.py set-limits`. |
| `USAGE_REQUESTS_PER_MINUTE` | No | `*=60` | Authorized attempts per user per calendar minute, by role, in the same shape and with the same validation — e.g. `*=60,admin=120`. The window is fixed, not sliding, and on the database's clock, so every instance shares it. |
| `BREAK_GLASS_INGRESSES` | No | `query,chat` | Where `ADMIN_TOKEN` may submit queries: any subset of `query` (`POST /query`) and `chat` (the chat UI), or empty for neither. `v1` is a **startup error** — the token is never accepted on the OpenAI-compatible endpoint, and this setting can only narrow where it is accepted, never widen it. Names are case-sensitive. The admin console is not affected. |
| `REPORTS_AGENTS_DIR` | No | *(repo-root `.agents`)* | Directory the Reports section reads PRD boards, stories and reports from. |
| `REPORTS_REPO_URL` | No | `https://github.com/The-Spik3r/harness-ai` | Repository a report's commit SHA links to, as `{REPORTS_REPO_URL}/commit/{sha}`. |
| `OPENROUTER_BASE_URL` | No | `https://openrouter.ai/api/v1` | Upstream base URL; `/chat/completions` is appended. It exists so end-to-end runs can point the harness at the stub upstream (`scripts/stub_openrouter.py`). Must be `https://`, or `http://` only on a loopback host (`127.0.0.1`, `localhost`, `::1`); anything else is a **startup error**. **Whoever controls this host receives `OPENROUTER_API_KEY`**, so it is an operator-only setting: treat changing it like handing out the key. Ignored in file mode (`PROVIDERS_FILE` set): each provider has its own `base_url`. |
| `PROVIDERS_FILE` | No | — (empty) | Path to the provider registry YAML; [`examples/providers.yaml`](../examples/providers.yaml) is a working sample. Empty keeps the implicit OpenRouter provider and today's behaviour, byte for byte. An invalid file is a **startup error** in both the API and the chat UI, naming the file, the provider or model and the rule. No hot reload: restart to change it. **Whoever controls a provider's host receives its key and every prompt**, so the file is operator-only. See [Providers](features.md#providers). |
| `V1_ENABLED` | No | `true` | Mount the [OpenAI-compatible endpoint](features.md#openai-compatible-endpoint). `false` leaves its routes out, so `/v1/*` is a `404`, and `POST /query` and the chat UI are exactly as they are with it on. |
| `V1_SSE_KEEPALIVE_SECONDS` | No | `10` | Seconds between `: keep-alive` lines on a `stream: true` response while the pipeline runs, so proxies and clients do not time out a long answer. Greater than `0` and at most `60`; anything else is a **startup error**. |
| `V1_TOOLS_ENABLED` | No | `false` | Tool calling on `/v1`. Off keeps PRD-015's `tools_not_supported` refusal byte for byte. On admits `tools`, `tool_choice`, `parallel_tool_calls` and tool turns, and decides every tool call the model returns with the action policy before the client sees it; `functions` / `function_call` are refused either way. Read at startup, so changing it needs a restart. **Configure `ACTION_POLICY_FILE` first.** See [Tool calling](features.md#tool-calling). |
| `V1_TOOL_MODELS` | No | — (empty) | Comma list of the models a `tools` request may name, exact match. Empty means no extra restriction. Every entry must also be in `MODEL_ALLOWLIST`, or startup fails naming it. When set it applies to every caller, `admin` and RBAC-off included; an unlisted model is `400 tools_not_supported`. See [Tool calling](features.md#tool-calling). Ignored in file mode, and a non-empty value with `PROVIDERS_FILE` set is a **startup error**: declare `capabilities: {tools: true}` per model instead. |
| `ACTION_POLICY_FILE` | No | — (empty) | Path to a YAML action policy; [`examples/action_policy.yaml`](../examples/action_policy.yaml) is a working sample. Empty uses the built-in policy and reads no file. A section the file states replaces the built-in one wholesale (`rules:` merges per rule id), and an invalid file, including a relative workspace root, is a **startup error** in both the API and the chat UI. Decides every `/v1` tool call when `V1_TOOLS_ENABLED=true`. See [Action policy rules](features.md#action-policy-rules). |
| `ACTION_MAX_ARGUMENT_CHARACTERS` | No | `100000` | Most characters in one tool call's `arguments` string; a longer one is denied as `tool.malformed` and never parsed. Must be at least `1`: `0` is a startup error, not "no ceiling". |
| `ACTION_SQL_DIALECT` | No | — (empty) | sqlglot dialect for the statements of SQL tools. Empty uses sqlglot's generic dialect; a name sqlglot does not know is a **startup error**. SQL embedded in a shell command (`psql`, `mysql`, `sqlite3`) always uses that client's own dialect, and this setting is not part of the policy digest. |

Every setting in this table is read once at startup (`app/config.py`); changing any of them requires a restart.

See [`.env.example`](../.env.example) for a ready-to-copy template with inline descriptions.
